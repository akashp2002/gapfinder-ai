# GapFinder AI

GapFinder is a diagnosis-first study assistant: it should identify learning gaps from a student's own material, then help prioritize revision. This project is being built in small milestones.

## Current milestones

- **Dashboard:** responsive study-health overview with clearly labeled sample data.
- **Material ingestion:** upload PDF, TXT, or Markdown; extract text, split it into source chunks, and preview citations.
- **Demo persistence:** extracted chunks are saved in the current browser with IndexedDB. They do not sync across browsers or devices.
- **Source labeling:** uploads can be marked as study material, syllabus, or past paper.
- **RAG diagnostic quiz:** retrieve relevant chunks locally, show their citations, generate multiple-choice questions from those excerpts with Groq, and save scored attempts in IndexedDB.
- **Gap report:** classify tested topics from each topic's latest quiz score and explain missed answers with their source sections.
- **Adaptive revision plan:** prioritize diagnosed topics, fit sessions to the student's available time, and update the priorities after new quiz attempts.

Explain-this-topic chat and account-backed persistence are not implemented yet.

## Run locally

Requires Node.js 22.3 or later and npm.

```bash
npm ci
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). The dashboard uses sample data; material upload is at `/materials`, the diagnostic quiz is at `/quiz`, the gap report is at `/report`, and the revision plan is at `/plan`.

Useful checks:

```bash
npm run lint
npm run build
```

Copy `.env.example` to `.env.local` and add a Groq API key before generating quizzes:

```powershell
Copy-Item .env.example .env.local
```

Set `GROQ_API_KEY` in `.env.local`. `GROQ_MODEL` is optional and defaults to `openai/gpt-oss-20b`. Never commit `.env.local`; the API key is only read by the server route. Configure the same variables in Vercel before deployment.

## Material ingestion

`POST /api/materials` accepts multipart form data with a `file` field and an optional `sourceKind` value: `study_material`, `syllabus`, or `past_paper`. The response includes extracted source chunks with citations:

- PDFs are cited by page number.
- TXT and Markdown files use recognized chapter/section headings when present, otherwise `Full text`.
- Chunks are about 900 characters with a 120-character overlap.

Uploads are limited to 4 MB, 120 PDF pages, and 700,000 extracted characters. Scanned image-only PDFs are not OCR-processed. PDF bytes are sent to this app's API route for extraction; no AI model is called during upload. The extracted text is stored in this browser's IndexedDB, so clearing browser data removes it.

## RAG quiz flow

1. **Retrieval:** the browser ranks the saved chunks against the requested topic using term frequency, inverse document frequency, and a section-heading boost. It selects up to eight chunks and displays the citations before generation.
2. **Generation:** `/api/quiz/generate` receives only those retrieved excerpts and sends them to Groq. The prompt requires source-only questions; response validation checks the question schema and that every citation refers to a retrieved chunk.
3. **Diagnosis:** the student answers the generated questions, receives explanations and source citations, and the scored attempt is saved in browser storage.
4. **Gap report:** the latest score per tested topic determines its strength band; missed questions are grouped by their cited source sections. Topics with no attempt remain unassessed.
5. **Revision plan:** the latest gap report prioritizes the topics, then allocates sessions within the saved exam-day and study-hours budget. Schedule preferences and quiz attempts are stored in the browser's IndexedDB.

The answer key and explanations are generated by the model and validated for structure and source IDs, not independently fact-checked. Review generated content before using it for high-stakes assessment.

The report uses fixed score bands: Weak below 50%, Medium 50-79%, and Strong 80% or higher. Each new attempt replaces the prior attempt as that topic's current diagnosis while keeping the attempt history.

The revision plan gives more time to weaker topics and uses lexical matches against chunks tagged as past papers as an **approximate** exam-emphasis signal. This is not question-frequency analysis: the app does not extract or count individual questions from past papers. Untested topics are not assigned a strength or scheduled.
